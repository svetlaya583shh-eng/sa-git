# Запрос данных на бэкенд: заказы клиента за период

## 1. Идентификатор запроса

- Код запроса: `GET_CUSTOMER_ORDERS`
- Автор: Иванов Иван
- Дата создания: 2026-10-20
- Статус: черновик
- Связанная задача: SA-123

## 2. Бизнес-цель

Менеджеру по работе с клиентами необходимо получать список заказов клиента
за выбранный период, чтобы анализировать историю покупок и готовить персональные
предложения.

## 3. Пользовательская история

Как менеджер по работе с клиентами,
я хочу получить список заказов выбранного клиента за период,
чтобы оценить его покупательскую активность и подготовить предложение.

## 4. Требования к запросу

### 4.1. Метод и endpoint

- Метод: `GET`
- Endpoint: `/api/v1/customers/{customer_id}/orders`
- Версия API: `v1`

### 4.2. Параметры пути

| Параметр | Тип | Обязательность | Описание |
|---|---|---|---|
| `customer_id` | UUID | Да | Уникальный идентификатор клиента |

### 4.3. Query-параметры

| Параметр | Тип | Обязательность | Значение по умолчанию | Описание |
|---|---|---|---|---|
| `date_from` | date, `YYYY-MM-DD` | Нет | Первый день текущего месяца | Начало периода включительно |
| `date_to` | date, `YYYY-MM-DD` | Нет | Текущая дата | Конец периода включительно |
| `status` | string | Нет | — | Фильтр по статусу заказа: `new`, `paid`, `shipped`, `cancelled` |
| `page` | integer | Нет | `1` | Номер страницы |
| `page_size` | integer | Нет | `20` | Количество записей на странице, максимум `100` |

### 4.4. Правила валидации

- `date_from` не может быть позже `date_to`.
- Период не может превышать 366 дней.
- `page` должен быть больше или равен `1`.
- `page_size` должен быть в диапазоне от `1` до `100`.
- Значение `status`, если передано, должно входить в допустимый список.

## 5. Ожидаемый ответ

### 5.1. Успешный ответ

- HTTP-статус: `200 OK`
- Формат: `application/json`

```json
{
  "data": [
    {
      "order_id": "0b8b3f52-1f22-4d61-9d3e-3f9f1b1c1234",
      "created_at": "2026-10-15T12:30:00Z",
      "status": "paid",
      "total_amount": 12500.00,
      "currency": "RUB",
      "items_count": 3
    }
  ],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total_items": 1,
    "total_pages": 1
  }
}
```

### 5.2. Ошибки

| HTTP-статус | Код ошибки | Условие | Сообщение пользователю |
|---|---|---|---|
| 400 | `INVALID_DATE_RANGE` | `date_from` позже `date_to` | «Дата начала периода не может быть позже даты окончания» |
| 400 | `PERIOD_TOO_LONG` | Период больше 366 дней | «Максимальный период выборки — 366 дней» |
| 400 | `INVALID_STATUS` | Недопустимый статус | «Передан недопустимый статус заказа» |
| 404 | `CUSTOMER_NOT_FOUND` | Клиент не найден | «Клиент не найден» |
| 401 | `UNAUTHORIZED` | Отсутствует или недействителен токен | «Требуется авторизация» |
| 403 | `FORBIDDEN` | Нет доступа к данным клиента | «Недостаточно прав для просмотра заказов клиента» |

## 6. Нефункциональные требования

- Время ответа: не более 1 секунды для выборки до 100 записей.
- Доступ: только авторизованные пользователи с правом `orders:read`.
- Логирование: фиксируются `customer_id`, пользователь, период выборки и результат запроса.
- Персональные данные: в ответе не передаются адрес, телефон и платёжные реквизиты.
- Доступность: сервис доступен в течение 99,9% времени (не более 8 часов простоя в год)

## 7. Критерии приёмки

- [ ] Запрос возвращает заказы только указанного клиента.
- [ ] Фильтрация по периоду работает включительно по границам.
- [ ] Фильтр по статусу возвращает только заказы с указанным статусом.
- [ ] Пагинация возвращает корректные `page`, `page_size`, `total_items` и `total_pages`.
- [ ] При некорректных параметрах возвращается понятная ошибка.
- [ ] Неавторизованный запрос получает `401 Unauthorized`.
